# espn_fantasy_stats

**Production app: https://espn-fantasy-stats.vercel.app**

> Access is invite-only. To request a login code, open an issue or email ronanprugh@gmail.com.

Multi-user web app for analyzing ESPN Fantasy Football leagues across seasons.

- **Backend**: FastAPI + SQLAlchemy + Postgres, wrapping the `espn_api` library.
- **Frontend**: React + Vite + TypeScript with Recharts for visualization.
- **Auth**: invite-only, bcrypt-hashed passwords, cookie sessions.
- **Storage**: Postgres (local via Docker; Neon in production). ESPN credentials encrypted at rest with Fernet.
- **Hosting**: Render (backend, free tier) + Vercel (frontend). Push to `main` auto-deploys both.
  Render's free instance sleeps after 15 min idle; `.github/workflows/keep-warm.yml` pings it
  during waking hours, so expect a ~50s cold start on the day's first visit.

What's in it:

- **This Week**: the front page. Your team's record, standing, streak and game, this week's matchups,
  the standings in brief and the latest power rankings (last season's champion in the offseason).
- **Standings / All-Time**: a season's standings, or every owner's career totals and every team-season
  ranked, with sortable columns, close-game records and an advanced-stats toggle.
- **Scoreboard**: a week's matchups as score cards with Top and Low score badges. Step or swipe through
  weeks, and open the box score of any 2019+ game.
- **Box Score**: both lineups slot by slot, mirrored about the slot on a phone.
- **Playoff History**: SVG bracket reconstruction with championship and consolation paths. Click any match
  for its box score.
- **Team Hub**: one owner's summary (record, standing, trophies, career records), roster, schedule,
  transactions and power rankings.
- **Trends**: a year-over-year line chart of any stat for the owners you pick, against the league average.
- **Head to Head**: one owner's record against everyone, or every meeting between two owners.
- **Positional Stats**: points each team scored from each lineup position, by season or all-time (2019+).
- **Transactions**: trades (decided by WAR, wins above replacement), waiver claims, free-agent pickups
  and drops, by season or all-time, with records (2019+). Pick a team to see only its moves: its trades
  from its side, its record, best and worst trade, and who it traded with; or its roster at the start of a
  season beside its roster at the end, with how each player joined or left.
- **Power Rankings**: a league's posted power rankings, imported from a file. Week-by-week rankings with
  every write-up, a season bump chart, all-time records and a searchable archive. Ranks also show up on
  Standings, Team Hub, Trends, Head to Head and the Scoreboard. Weeks with no posted rankings take the
  nearest week's ranks and are always marked as assumed.
- **API tokens**: read-only personal tokens (Account page) for scripts and assistants, sent as
  `Authorization: Bearer efs_…`.

## First-time setup

### 1. Clone and start Postgres

```bash
git clone https://github.com/ronanprugh/espn_fantasy_stats.git
cd espn_fantasy_stats
docker compose up -d                   # starts Postgres on localhost:5432
```

Data lives in `./.pgdata` (gitignored) and survives container restarts.

### 2. Backend setup

```bash
cd backend
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env                   # then fill in the two keys below
```

Generate the two required secrets and append them to `.env`:

```bash
python -c "import secrets; print('SECRET_KEY=' + secrets.token_urlsafe(32))" >> .env
python -c "from cryptography.fernet import Fernet; print('ENCRYPTION_KEY=' + Fernet.generate_key().decode())" >> .env
```

(Optional) if you want the `seed-from-env` shortcut below, also add your first
league's ESPN values to `.env`:

```
LEAGUE_ID=1375368
ESPN_S2=AEAC...
SWID={...}
```

Apply the migrations:

```bash
.venv/bin/alembic upgrade head
```

### 3. Create your first user

New accounts require an invite code generated by an admin. In production the admin
generates a code from the Account page (Settings → Invite a new user). Locally,
accounts can also be created directly via the admin CLI:

**Option A — from scratch:**

```bash
.venv/bin/python -m app.admin create-user --username ronan --admin
# prompted for password; --admin lets this user generate invite codes
.venv/bin/python -m app.admin add-league \
  --username ronan \
  --league-id 1375368 \
  --name "Walter Payton Bertoni Bowl" \
  --espn-s2 "AEAC..." \
  --swid "{...}"
```

**Option B — one-shot seed from `.env`** (requires LEAGUE_ID/ESPN_S2/SWID set):

```bash
.venv/bin/python -m app.admin seed-from-env --username ronan --name "My League"
```

### 4. Start the backend

```bash
.venv/bin/uvicorn app.main:app --reload --port 8000
```

### 5. Frontend setup (new terminal)

```bash
cd frontend
npm install
npm run dev
```

Open http://localhost:5173 and sign in with the credentials you set in step 3.

## Daily use

Once everything is installed, three commands get you running:

```bash
# Terminal 1 — Postgres (skip if already up: `docker ps` to check)
docker compose up -d

# Terminal 2 — backend
cd backend && .venv/bin/uvicorn app.main:app --reload --port 8000

# Terminal 3 — frontend
cd frontend && npm run dev
```

Stop everything:

```bash
docker compose down                    # Postgres
# Ctrl+C in the uvicorn and vite terminals
```

## Managing users and leagues

In production, invite new users from the **Account** page — generate a code with an
expiry and max-use count, then share it. Recipients visit the app, click
"Create an account", and enter the code alongside their chosen username and password.

To add a user directly via CLI (local/dev only):

```bash
cd backend
.venv/bin/python -m app.admin create-user --username <name>
```

Then they log in and add their own leagues via the **Manage Leagues** page in the UI
(or you can pre-attach a league for them with `add-league`).

List all users and how many leagues each has:

```bash
.venv/bin/python -m app.admin list-users
```

Make someone an admin (able to generate invite codes), or take it away:

```bash
.venv/bin/python -m app.admin set-admin --username <name> [--revoke]
```

## Getting your ESPN cookies (for private leagues)

1. Log into [fantasy.espn.com](https://fantasy.espn.com) in a browser.
2. Open DevTools → Application → Cookies → `https://fantasy.espn.com`.
3. Copy the `espn_s2` and `SWID` values.
4. Paste them in the "Add a league" form in the UI, or pass via the admin CLI.

The cookies are encrypted with Fernet before being written to Postgres. Public
leagues don't need cookies — leave the fields blank.

## Database migrations

Schema lives in `backend/alembic/versions/`. When you change a model:

```bash
cd backend
.venv/bin/alembic revision --autogenerate -m "describe change"
.venv/bin/alembic upgrade head
```

In production, migrations apply themselves: when a change under
`backend/alembic/` lands on `main`, the `migrate` workflow
(`.github/workflows/migrate.yml`) runs `alembic upgrade head` against Neon.
It needs one repository secret, `DATABASE_URL` (Settings → Secrets and
variables → Actions), holding the Neon connection string in the same form as
Render's (`postgresql+psycopg://…?sslmode=require`; Neon's direct host, the one
without `-pooler`, is best for schema changes). It can also be run by hand from
the Actions tab. Keep migrations additive (new tables and columns) where you
can: Render deploys the same push at the same time, so for a minute the old
code may run against the new schema.

To reset the local DB completely (nuke all users, leagues, and cached ESPN data):

```bash
docker compose down -v                 # -v removes the volume too
rm -rf .pgdata
docker compose up -d
cd backend && .venv/bin/alembic upgrade head
# then re-seed your user
```

## Power rankings

Rankings come from an import file, not ESPN, so nothing about them is in the repo. Open **Power Rankings** →
**Archive** (or the empty state on a league with none yet) and upload a JSON file shaped like the example on that
screen. Importing replaces the league's whole archive, for everyone who has added the league.

Each post's `week` is the week it looks ahead to: preseason rankings are week 1, and rankings written after Week 3's
games are week 4. Entries name teams by `team_name` (any name the team has used, or its abbreviation) or ESPN
`team_id`; an import with a name that matches no team is rejected whole, with the names listed.

## Error reporting (optional)

Both halves can report errors to [Sentry](https://sentry.io) (free tier is plenty), and
do nothing until given a DSN:

- **Backend:** set `SENTRY_DSN` on Render. Our bugs and unhandled exceptions are
  reported; ESPN being down isn't.
- **Frontend:** set `VITE_SENTRY_DSN` on Vercel (it's read at build time, so redeploy).
  The SDK is only downloaded when it's set.

Reports never carry cookies, Authorization headers, request bodies, IPs or the ESPN
cookies; see `backend/app/reporting.py` and `frontend/src/lib/reporting.ts`.

## Troubleshooting

- **`SECRET_KEY env var is required`** — you skipped step 2's secret generation, or `.env` isn't being loaded. Check that `backend/.env` exists.
- **`Could not connect to localhost:5432`** — Postgres isn't running. `docker compose up -d` to start it.
- **Backend crashes on first request** — Alembic migrations weren't applied. Run `.venv/bin/alembic upgrade head` from the backend dir.
- **Login returns 401 for the right password** — the bcrypt hash uses a per-install pepper indirectly via the password itself. Make sure you created the user under the same `SECRET_KEY` you're using now (rotating the key doesn't invalidate passwords, but does invalidate sessions).
- **Box score links don't work for old seasons** — `espn_api` only supports box scores from 2019 forward. Pre-2019 matchup rows are non-clickable by design.
- **Transactions says ESPN didn't return a season** — ESPN gave nothing for it from either the activity feed or the transactions view. The page tries again after the next refresh point. To see what ESPN returns for each season of your league, run `.venv/bin/python scripts/diagnose_transactions.py` from `backend/` (it reads `LEAGUE_ID`, `ESPN_S2` and `SWID` from `.env`).
- **No one can generate invite codes** — nobody is an admin yet. Run `python -m app.admin set-admin --username <name>` against that database.
